# MongoDB Atlas Vector Search Index Configuration Guide

DocuMind AI uses **MongoDB Atlas Vector Search** to perform ultra-fast approximate nearest neighbor (ANN) semantic retrieval over high-dimensional chunk vectors.

---

## 1. Prerequisites
- An active MongoDB Atlas cluster (M0 Free Tier or higher, MongoDB version >= 6.0.11 or >= 7.0.2).
- The `documind_db` database with the `document_chunks` collection created.

---

## 2. Atlas Vector Search Index Schema Definition

In the MongoDB Atlas UI:
1. Navigate to your cluster and select **Atlas Search** (or **Search and Vector Search**).
2. Click **Create Search Index**.
3. Choose **Atlas Vector Search** > **JSON Editor**.
4. Select the target database: `documind_db` and collection: `document_chunks`.
5. Enter index name: `vector_index` (matching `MONGODB_VECTOR_INDEX` in `.env`).
6. Paste the following JSON definition:

```json
{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 384,
      "similarity": "cosine"
    },
    {
      "type": "filter",
      "path": "document_id"
    },
    {
      "type": "filter",
      "path": "filename"
    }
  ]
}
```

---

## 3. Explanation of Field Roles

| Field Path | Type | Purpose |
| :--- | :--- | :--- |
| `embedding` | `vector` | Stores the 384-dimensional dense vector generated by `sentence-transformers/all-MiniLM-L6-v2`. Uses `cosine` distance metric to rank semantic similarity between 0.0 and 1.0. |
| `document_id` | `filter` | Allows targeted queries restricted to a single uploaded document (e.g., scoping a chat question to only `Invoice_1001.pdf`). |
| `filename` | `filter` | Allows metadata filtering by exact document name. |
| `text` | `string` | Stored in the chunk document (not indexed directly in vector index) and retrieved via projection during aggregation for prompt augmentation. |

---

## 4. Query Pipeline Architecture ($vectorSearch)

DocuMind AI issues the following aggregation pipeline via PyMongo:

```json
[
  {
    "$vectorSearch": {
      "index": "vector_index",
      "path": "embedding",
      "queryVector": [<384 floats>],
      "numCandidates": 100,
      "limit": 4,
      "filter": {
        "document_id": { "$eq": "doc_12345" }
      }
    }
  },
  {
    "$project": {
      "_id": 0,
      "chunk_id": 1,
      "document_id": 1,
      "filename": 1,
      "page_number": 1,
      "chunk_index": 1,
      "text": 1,
      "score": { "$meta": "vectorSearchScore" }
    }
  },
  {
    "$match": {
      "score": { "$gte": 0.35 }
    }
  }
]
```

---

## 5. Offline & Development Fallback

If `MONGODB_URI` is omitted or the search index is not yet built, DocuMind AI seamlessly falls back to an **In-Memory Simulated Vector Store**. It computes true cosine similarities across all stored chunks in memory, ensuring you can develop, test, and demo without any paid cloud dependencies.
